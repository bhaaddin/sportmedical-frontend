## R20a - the liquid

- Before (`before-*.png`): `.liquid-water` was one teal gradient with two pseudo-element wave strips that translate 2-6 px; on a 33 px
  orb that reads as standing still, and every činnost drew the same teal.
- Now (`design/stage3a/lab-0..2.png` - the demo planner has multi-činnost days; the dev clinic data has mostly one činnost per day,
  so the real `/planovani` shows one band per day): `miniCellModel(...).ring.layers` (new, `model/dayPlan.ts` `liquidLayers`) is one band
  per činnost of the day, grouped like the agenda (`groupByActivity`), height = the činnost's share of the day's SLOTS (a booking
  counts the people booked, a window its capacity; a day without slots weighs by minutes), colour = the činnost's `activityColor`
  (`category.color`), at most 3 bands, the largest ones kept in the catalogue's order (like the ring's arcs), the others merged into
  one grey `další` band on top (`#8795a3`, never a činnost colour). The level of the liquid (`liquidPercent`, usage against the day
  budget) and the golden-tested ring arcs are unchanged.
- Drawing (`MiniDayButton`, `left/left.css`): one `<i class="liquid-layer">` per band, highest first, each the column up to its own
  top (`--cum`), literal inline colour `--c` (the accent shift never reaches it), a sine wave crest on top (SVG mask, one period per
  orb width, the element is twice as wide and slides exactly one period = a seamless loop; neighbouring bands run at different speeds,
  directions and phases, so the colours visibly slosh against each other), plus a slight rock of the whole water (`rotate` +/-3 deg,
  `translateY` +/-0.6 px). Everything animated is a `transform`: no layout, composited.
- Motion setting (the existing `html[data-motion]`): `plné` = waves + rock; `omezené` and `vypnuto` = the same picture, still
  (the stage's choice among "still with colour drift or static": static, cheapest); the device's `prefers-reduced-motion` always means
  still. Animations only run while `#mini-days` is on screen and the tab visible (`useLiquidLive`: IntersectionObserver +
  `visibilitychange` -> `#mini-days[data-liquid="paused"]` -> `animation-play-state: paused`); a closed tablet drawer / phone sheet is
  off screen, so nothing runs there.
- Ring (R16a): the arcs were already one per činnost in its colour (golden-tested against the prototype, not touched).
- Cost (`scripts/stage3a/liquid-perf.mjs`, CPU x4, 4 s of board zoom + wheel scroll, 1440x900, 13 banded days = 24 running animations):
  `vypnuto` p50 17.7 ms / p95 18.1 ms / 0 frames over 50 ms / 0 long tasks; `plné` p50 17.9 / p95 18.1 / 0 / 0 (two runs each, same
  numbers). No measurable cost.
- Tests: `model/liquidLayers.test.ts` (0..6 činnosti, merge into `další`, largest kept, booking people vs free seats, minutes fallback,
  part of the cell model), `left/MiniDayButton.clubs.test.tsx` (bands, order, `--cum`, plain water without bands),
  `left/useLiquidLive.test.tsx` (pauses off screen / hidden tab), Playwright `scripts/stage3a/r20-check.mjs` (crest transform changes in
  500 ms; `vypnuto` and `omezené` -> nothing moves).

## R20b - nothing under the mini calendar

- `AgendaPanel` draws nothing when there is no club (`useClubPlanner() === null`) and the catalogue's mode is `standard`: the Činnosti
  pills, the činnost card (slots / price) and "Termíny činností v kalendáři" are gone from the desktop column, the pinned tablet column,
  the tablet drawer and the phone sheet, one rule for all three. A club's order screen and a club's overview still draw it.
- Decision (by looking at the screens): the CALENDAR grows, the board does not get the width (the column stays 417 design px wide, the
  board's geometry is the stage's and untouched). The mini calendar takes the whole column: the six day rows share the height
  (`minmax(50px, 1fr)`), the circles grow with the room (`--cell` = min(column / 7, row, 66 px): ring 98 %, liquid 70 %, number
  16.5-22 px), the legend sits at the bottom. Same for the pinned tablet column (>= 1000 px; rows >= 48 px, cells <= 60 px). The
  rules are in `planner.fluid.css` / `planner.compact.css` behind `:not(:has(.agenda-panel))`, so a club's column is untouched; the
  generated `planner.css` was not edited.
- Measured (`r20-check.mjs`): no gap under the legend (13-16 px at 1440 / 1920, 13 px pinned at 1100), the document never scrolls at
  320, 360, 390, 820, 1100, 1440, 1920. The rows are airy at 1920 (rows ~120 px): the circles are limited by the column width
  (~55-60 px), the free height is spread between the rows.
- Tests: `left/AgendaPanel.test.tsx` "R20" (standard mode draws no panel, club mode keeps it); the older demo tests (club order and
  demo "standard" without catalogue mode) pass unchanged.

## R20c - "Kalendáře"

- `CalendarStrip`: label "Kalendáře"; one chip per calendar group: ICON + the calendar's own name ("Ordinace 1", "Diagnostika", "InBody",
  "Balíčky" - from `calendarsApi`; the služba's name is the tooltip and still the column head) + "Všechny" (now always there, selected
  while nothing is narrowed). Selected = filled in the calendar's colour with a ring and a solid icon disc; the others are dim and
  hollow. Click toggles (same rules as stage 2: from "Všechny" one click shows only that calendar, a second adds a column, hiding the
  last is "Všechny").
- Icons (`board/calendarIcon.ts`): picked from the planner's own sprite by keywords in the calendar name, then the služba name:
  balíčky -> dumbbell, inbody / tělesná -> physio, diagnostika / spiro -> gauge, ordinace / prohlídka / lékař -> heart, klub -> users,
  sport -> run, anything else -> calendar. No clinic name is hard-coded; a test proves it only ever returns a sprite name.
- Phone (<= 767): one equal tile per calendar (icon over the name), all five on one row at 320-767 px, 52 px high; tablet / desktop
  chips are 44 px high on touch layouts. The "Víc než 3 kalendáře ..." hint (existing, shown while every calendar is on and the
  board is not split) and the činnost pills inside the strip (R2, shown only after narrowing, hidden on a phone) were not touched.
- The `Všechny služby` dropdown (`#activity-filter`, stage 1) is gone from the main calendar's toolbar (`BoardToolbar` draws the select
  only for a club's own board; the unreachable service branch was deleted). Club planner: its "Všechny činnosti" select is unchanged.
- Tests: `BoardToolbar.test.tsx` (no select on the main calendar, club keeps its činnost select with prices), `calendarIcon.test.ts`,
  `WeekBoard.calendars.test.tsx` (chip names, icon, label, "Všechny" pressed, click rules), Playwright `r20-check.mjs` per width
  (icons, label, no `#activity-filter`, one click = one calendar, second adds, Všechny resets, >= 44 px on touch layouts).
