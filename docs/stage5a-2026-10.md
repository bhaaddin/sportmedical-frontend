# Stage 5a - the club has its own PAGE (R7), the calendar is one click further

Owner, 22. 10. 2026: "a club must first have a PAGE, and then the calendar". Flow (R7): Přehled -> Kluby a týmy -> the list -> a club ->
**the club's page** (a few shelves with the statistics) -> only after "Kalendář" the planner with all orders.
Branch `stage/5a-club-page` (from `claude/clean` e39b308), not pushed.

## Flow

```
/clubs (list)  --click a club-->  /clubs/:clubId  (PAGE: header, Statistiky, Objednávky, Nejbližší termíny, Poslední změny, Hráči, Odkazy)
                                       |  "Kalendář" (the one prominent button; hover/focus/touch warms the calendar's code and reads)
                                       v
                                  /clubs/:clubId/kalendar  (the planner in club mode, unchanged)
                                       |  "Zpět na klub" (desktop/tablet button next to Menu; phone: the top bar's trail  Kluby a týmy > Klub > Kalendář)
                                       v
                                  /clubs/:clubId
```

Model (pure, tested): `clubOverviewModel.ts`. Every shelf has loading / empty (with the next action) / error (with retry). **A source that cannot be read is
a dash with the reason ("Nepodařilo se načíst.", "Bez oprávnění k fakturaci.", "Načítám…"), never zero**; all of statistics / orders / blocks failing at once is one error with one retry.

## Decisions

* Six figures, no more (`MAX_METRICS`); next terms and the billing warning are not figures - they are a shelf and a header chip.
* Invoiced / paid come from the club's invoices (Issued, PartiallyPaid, Paid; drafts, cancelled, pending are not billing). They are read behind the rest and
  only for a person who may bill; without the permission the two cards say so and the request is never sent.
* Page, not planner: PageFrame + Shelf (shelf design system), three layouts via `useDevice`, the document never scrolls (shelves scroll sideways / inside).
* `PageFrame` / `ShelfAction` got an optional `onIntent` (pointer / focus / touch on the primary button) - generic, used for the warm-up.
* The planner keeps its overview deck and the "Přehled klubu" dialog (the dialog still holds merge / cancel / legacy reservations that the page does not duplicate).
  **Not trimmed** - see open risks.
* Light theme: `DESIGN.muted` `#67707A` -> `#626B75`. Secondary text on the light PAGE background was 4.44:1 (AA needs 4.5) on every shelf page; pinned in `theme.contrast.test.ts`, fixture updated.
* The phone has no Menu button, so the where-am-I trail got `Kluby a týmy > Klub > Kalendář` (the middle crumb is the way back).

## Speed

Warm-up: a club card's hover/focus/click -> `prefetchClubPage` (club + orders seeded from the list, windows, summary, the history of the 3 newest orders, the page's code - nothing of the calendar);
a direct address opens the same; the page's "Kalendář" button -> `prefetchClubScreen` (calendar chunk + stage reads, once per visit). Dev server, 1440x900, +80 ms on every `/api/` call, 3 runs, medians (`scripts/stage5a/speed.mjs`, `design/stage5a/speed.json`):

| Variant | ready | API requests | depth |
|---|---|---|---|
| page, cold deep link | 2239 ms (dev compiles modules) | 12 | 2 |
| page, from the list, click at once | ~500 ms | 9 | 2 |
| calendar from the page, click at once | 594 ms | 22 | 3 |
| calendar from the page, pointer rested on Kalendář | 512 ms | 2 after the click | 1 |

The page itself gains little from a resting pointer: the club and its orders are already shared from the list. The invoices no longer hold the statistics back (added after the table was measured).
