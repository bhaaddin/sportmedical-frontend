# Stage 9 (24. 10. 2026): Nastavení > Komunikace > E-mail (R25)

What it is: a settings page that reports the e-mail sender and sends one test message. Nothing is edited on it; the provider key and the sender address live only in the server environment (guide: `sportmedical-ops/docs/EMAIL-SETUP.md`, backend copy `docs/engineering/email-setup.md`).

## Where
- Route `/nastaveni/email`, permission `settings.clinic.manage`, catalogue id `email-odesilani` (group Komunikace, keywords for search: email, smtp, brevo, spf, dkim, dmarc, ...).
- `src/pages/settings/EmailSettingsPage.tsx`, `emailStatusApi.ts` (zod-parsed; the schema has no key field), `emailStatusModel.ts` (pure Czech wording, address check, DNS checklist).

## What it shows
- Card "Odesílání": Nastaveno / Nenastaveno, provider, sender address, last successful send, queue, sent and failed in 24 h.
- "Poslat zkušební e-mail" pop-out: one address field; the result is worded from the server problem code (`email.not_configured`, `email.provider_rejected`, `email.timeout`, `email.provider_unavailable`, `email.invalid_address`) or the status (404 older server, 403, 429 = 3 per hour).
- Side card: the four DNS steps and a link to the guide.
- Older backend (404 on status): "Tato verze serveru ještě neumí e-mail přes API." and no test button.

## Checks
- Component + model tests: `EmailSettingsPage.test.tsx` (6 cases x 3 layouts), `emailStatusModel.test.ts`; catalogue pins updated (21 screens, 16 administration, Komunikace lists four).
- `scripts/email-check.mjs` (own headless Chromium, three layouts) against a backend on :5097 with a scratch copy of `sportmedical_dev` (dropped afterwards): document never scrolls, no horizontal overflow, targets >= 44 px, no console error or failed request; the real server answers "není nastaven" to the test send (nothing was sent). The configured card and the older-server state are drawn from `page.route` mocks, removed afterwards: the real dev server has no provider.
- Screenshots (JPEG) in `design/stage9/`.

## Limits
- Accent and Animace come from the theme and the shared frame; the page adds no colour literal and no animation of its own.
- The configured state was not seen against a real provider (no key, no real e-mail by instruction).
