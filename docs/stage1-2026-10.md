## R11 - the club link

- Reproduced: planner -> "Připravit formulář" -> "Vygenerovat odkaz" showed `/klub-objednavka/Wv__...` (no address), the e-mail
  preview had the same bare path, "Kopírovat odkaz" copied it (`scripts/stage1/r11-repro.mjs`, `design/stage1/r11-*.png`).
- "Odkaz neplatí": reproduced exactly. The fresh form token opened on `/klub-objednavka/<token>` loads the form (API 200 on
  `/api/public/club-order/<token>`); the SAME token on `/klub/<token>` says "Odkaz už není platný nebo vypršel"
  (`scripts/stage1/r11-wrongroute.mjs`, `r11-5-route-*.png`). The router has both routes and each needs its own token: the club form
  and portal use the order's club token (`/klub-objednavka/:token`), the players use the athletes' token (`registrationUrl`, `/klub/:token`).
  So the cause was the missing address, not the backend. **No backend change is needed.** (The backend sends a full URL when the setting
  `pub.siteUrl` is stored on the server side, otherwise a path.)
- Fix: `useLink()` in `PublishDialogs.tsx` goes through `absoluteLink` (public base `pub.siteUrl`, else `window.location.origin`);
  the e-mail text and "Kopírovat odkaz" use the same string. One `CopyButton` (`components/clubs/orders/CopyButton.tsx`, clipboard API
  then a textarea `execCommand` fallback, `Zkopírováno` for 2 s, `Nepodařilo se zkopírovat` when refused, theme colours, 44 px) stands beside
  the link in the publish dialog, in the e-mail preview and in every `LinkCopyRow` (order panel, invite dialog). `LinkCopyRow` shows the full
  address with `https://`. Readable colours: 14 px, `#e6fbff` on the dark dialog.
- Tests: `PlanDialogs.test.tsx` (bare path -> full link shown, copied, mailed, "Zkopírováno"), `clipboard.test.tsx` (API, fallback, refusal, 2 s),
  `absoluteLink.test.tsx` (full link, copied state). Browser: copied text equals the full link, state returns to idle after 2 s.

## R8 - prices

- Reproduced with a temporary unlink of "Základní sportovní prohlídka" on the dev stack (restored in `finally`): the main planner's
  filter said `Základní sportovní prohlídka · bez ceny`, the club planner said "bez ceny" (`scripts/stage1/r8-repro.mjs`). After the fix
  both say 1 600 Kč.
- Fix: `components/booking/price/priceOf.ts` (`priceFor`/`priceOf`: the figure the server read, else the linked price-list item, else the
  active item of the same name, accents and case ignored; `null` only when the price list has none). `activitiesApi.list` applies it, so
  every screen that reads the činnosti (board cards, deck cards, filter lists, bubble, summary, "Detaily po činnostech", mini lists, dialogs,
  shelves) shows the same resolved price; no view does its own lookup. The price list is read at most once a minute and a failed read leaves the list as it was.
- `scripts/check-prices.mjs <base url>` compares the public price list with `tests/fixtures/website-prices.json` (12 website prices,
  the combination packages are reported, not compared). Dev API: `OK - every website price is the same in our list`; exit 1 on a
  difference, 2 when the list cannot be read.
- Tests: `priceOf.test.ts` (link, name, active first, null only when none, normalisation, the fixture and the comparison),
  `activities.prices.test.ts`.
- Not covered by the frontend: the club ORDER's own price snapshot (`activitySeats[].unitPriceCzk`, `priceQuote`) is computed by the
  server through the same link. Linking the činnost to its price-list item (Nastavení -> Služby) fixes it; the owner's live data should be
  checked with `scripts/check-prices.mjs https://sportmedical-api.onrender.com` and the činnosti of the live data for a missing link.

## R12 - "Zobrazit detail po činnostech"

- Reproduced: all three činnosti of "Sportovní lékařské prohlídky" drew as `#17A291`, `#09423B`, `#29E1C9` - shades of one služba colour
  (the server's `effectiveColorHex`), the dot was 8 px and at 0 % nothing else carried the colour; `#09423B` is nearly invisible on the dark
  stage. The view already used the shared colour and showed the price lines.
- Fix: `onDarkSurface` (`colors/activityColor.ts`) lifts a činnost's mark until it shows on the dark stage (>= 3:1); the rows get a 4 px
  stripe, a 14 px ring swatch and a tinted bar track; the money lines and the compact bars carry a swatch. Test: `activityColor.test.ts`.
- Limit: while a činnost has no colour of its own the server draws it as a shade of its služba. Set own colours in Nastavení -> Barvy služeb
  a činností (or the backend default palette should spread the shades over distinct hues) to make them differ clearly; the frontend does not invent a second palette.

  "Objednat mimo nabídku" (override with a typed reason, `bookings.override`) is a separate documented feature and was NOT touched; say if it must go too.
- R15a: verified on every path of the main planner (board click, drag, toolbar button -> same dialog; quick registration too): choosing a
  činnost shows `Cena` prefilled with the list price, "podle ceníku", the total, editable, `Vrátit ceník`. New: the optional field
  `Důvod úpravy (nepovinné)` (only while the price differs; not in quick registration) travels in the booking note as `Důvod úpravy ceny: ...`.
  **There is no reason field in the appointments API**; an audited reason needs a backend field next to `agreedPriceCzk` (e.g. `agreedPriceReason`, max 200) -

- Tests: `NewAppointmentDialog.test.tsx` (no "Zkusit přesně", listed/unlisted typed minute), `NewAppointmentDialog.price.test.tsx` (reason, 3 widths).

## R9 - the činnost strip

- Reproduced at 1440 (`scripts/stage1/r9-measure.mjs before`): 3 činnosti -> 2 whole cards, third at `p`/hidden, "ještě 1"; tablet and phone the same.
- Fix: the count comes from a minimum card width (`DECK_MIN_CARD_WIDTH` 200 design px on the stage, `COMPACT_MIN_CARD_WIDTH` 160 px on the strip) instead
  of the file's 309.7 px; the compact cards are drawn from the same count (`--deck-nc`); a ResizeObserver re-measures the cards (the third card
  stayed at opacity 0 after the strip found room, which is why the earlier fix did not hold); names wrap to two lines on narrow cards.
- Result (whole + visible cards): desktop 1440: 1..3 činnosti all shown, 4 -> 3 + "ještě 1", 5 -> 3 + "ještě 2"; tablet 820: 1..4 shown, 5 -> 4 + "ještě 1";
  phone 390: 2 + "ještě N". The escalator, "NOVÁ" and the shake are untouched: `scripts/club-planning/deck-check.mjs` 339 checks ok, no failure.
- Tests: `PlannerMetrics.test.ts` (counts), `deck.test.ts` (1..8 činnosti x widths), browser measurement at 390/820/1440.
- Cost: on the desktop stage with 3+ cards each card is ~172 px; package names can still be cut after two lines (the full name is in the title/tooltip and the summary).
