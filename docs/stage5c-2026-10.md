Everything is a pop-out (the card, the callout, the dialog); no sidebar, no panel. The hint is one small card in the strip's own
box, directly above the cards (it can never cover a card or the dock), closes with x ("seen", does not come back) or with
"Nezobrazovat" (no more hints for this person), both 44 px on phone and tablet.

## The state function (pure, tested)

`guide/hints.ts`: `chooseHint(input, memory, now, clock) -> { hint, variant, waitMs }`. `input` is the planner state, read by
`GuideSlot` (`usePlanFigures`, view, armed činnost, callout open, dialog open, strip page, layout, cards that fit) - the DOM is
never read for a decision and no timer watches the DOM. Rules: one hint at a time; never while a dialog or the completion card
is open; at most one per 20 s (`HINT_GAP_MS`, counted from the moment the last one appeared; the same hint coming back after a
dialog is not "new"; the hint on screen is never removed by the gap; a waiting hint says how many ms it waits and the host asks
again then); priority `start` before `strip`; a hint whose job the person has done (`settled`: something planned, strip moved)
is seen for good, even if it never showed. Memory per person in `localStorage` (`sm-planner-hints:<user id | e-mail | name |
anon>`), read and written defensively: junk, wrong shapes, unknown ids, a throwing storage all mean "empty memory", never an error.

All texts are in `PLANNER_TEXT.guide` (`src/planner/text.ts`), reviewed for plain Czech (no jargon, one idea per sentence, correct
plural forms for the strip hint: 1 činnost, 2-4 činnosti, 5+ činností).

## Open risks

* On the desktop stage (a mouse layout drawn in design pixels and scaled) the hint's x / "Nezobrazovat" are about 37 px on screen at
  1440 wide; the 44 px rule is checked and met on phone and tablet.
* The hint sits above the strip, over the lower edge of the board; on the phone the strip is below the fold, so the hint appears when the person
  scrolls to the cards (the dock's own one-line hint is what shows before).
* The refusal advice is matched on the Czech wording of the existing messages (`refusalAdvice`); a new refusal sentence needs a line there
  (a test lists the known ones). "Přidat den" ("Pro ... není ... volný den") is not given advice.
* "E-mail preview" and the copy buttons of the publish dialog are now disabled until their step is done - a person who used to copy the
  text before generating the link (it carried a placeholder) must now generate first. That is the requested behaviour.
* The 20 s gap is per page load (a module variable), the "seen" memory is per person per browser.
