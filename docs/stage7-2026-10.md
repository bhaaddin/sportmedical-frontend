Owner, 22. 10. 2026: "Objednávky, co byly zrušeny, budou ve special rozhraní, kliknout na historie, jinak tam budou vidět jenom živé objednávky."
Branch `stage/s7` (from `claude/clean` ef2fb0e), not pushed.

## The rule

| Status | Where it is seen |
|---|---|
| Invited (Čeká na formulář), Requested (Odesláno klubem), Confirmed (Potvrzeno), **Completed (Dokončeno)** | every normal list and count ("live"; Completed stays - the owner spoke only about cancelled, open question 24 in `REPORTS-AND-PLAN.md`) |
| **Cancelled (Zrušeno)** | only the special view `/clubs/objednavky/historie`, one order's own history, a deep link to the order (read-only) |

One place says which is which: `components/clubs/orders/orderLogic.ts` -> `isCancelledOrder`, `withoutCancelled`, `onlyCancelled`
(not to be confused with `orderWindows.isLiveOrder`, which means "Requested / Confirmed" and is about money).

## Routes

| Address | Page |
|---|---|
| `/clubs/objednavky` | live orders; header: **Historie (n)** (outlined, before "Nová objednávka"; on a phone it is the only header button, "Nová objednávka" stays pinned at the bottom) |
| `/clubs/objednavky/historie` (`?clubId=`) | **new**: `ClubOrdersHistoryPage` - the cancelled orders |
| `/clubs/objednavky/:orderId/historie` | unchanged: ONE order's history |

The two history addresses have 3 and 4 segments, so react-router never reads `historie` as an order id; the new route is declared first anyway
(`StaffApp.tsx`). `plannerRoutes.ts` spells it (`CLUB_ORDERS_HISTORY_PATH`, `clubOrdersHistoryPath(clubId?)`); `objednavky` is a section, so the view is neither a
club's page nor the planner's stage. Tests: `plannerRoutes.test.ts`, `ClubOrdersHistoryPage.test.tsx` ("the two routes never meet": the three shapes through
react-router, plus a check that `StaffApp.tsx` declares the new address before the `:orderId` one).
`ClubOrderHistoryPage` "Zpět na objednávku" of a *cancelled* order leads to the Historie view (which opens it), not to the live list it is not in.

## The special view (`ClubOrdersHistoryPage`)

Header "Historie objednávek" - "Zrušené objednávky klubů - jen ke čtení", **Zpět na objednávky**. Filters: search (club name accent-insensitively, or `KO-` code),
Klub, Zrušeno od / do. Desktop: table (Klub, Objednávka, Služba, Termíny, Zrušeno, Důvod, Otevřít); tablet / phone: cards. **Otevřít** shows the order panel
(drawer; `{ openOrderId }` router state opens it at once). Empty: "Žádné zrušené objednávky." / "Tomuto filtru neodpovídá žádná zrušená objednávka.".

*Cancelled day and reason*: the list answers carry no history (measured in stage 5a), so they are read from each cancelled order's own answer (key
`['club-order', id]`, shared with the panel and the history page), newest first, for at most 60 orders; the newest history entry that mentions "zruš..." gives the
time and its wording is the "Důvod" (the desk's message or the plain "Zrušeno"). Where it cannot be read: a dash. A day filter keeps only orders whose day is known.
Model: `ordersHistory.ts` (`historyRows`), `orderLogic.cancellationOf`.

*Read-only*: `ClubOrderDetailPanel` offers a cancelled order **no footer action at all** (was: "Napsat klubu") and says "Zrušená objednávka - jen ke čtení";
the header's own "Historie" button stays. All edit/add/process/invoice actions were already gated to other statuses.

| Place | Before | Now |
|---|---|---|
| Kluby > Objednávky list, chips, counts | all five statuses, "Zrušeno" chip | live only; no "Zrušeno" chip; "Vše" counts live; Historie button carries the cancelled count (of the current club / date filter) |
| Club page - Objednávky shelf | cards of every order, cancelled last | live cards only; shelf count = live; **Historie (n)** button in the shelf header -> view pre-filtered to the club; empty text mentions the Historie when only cancelled exist |
| Club page - figures | see below | unchanged meanings |
| Club page - Poslední změny | the 3 orders touched last, cancelled included | the 3 live orders touched last (a cancelled order's events are in its history) |
| Club page - links / "Celá historie" | newest live order | unchanged (focus order is now taken from live orders) |
| Hráči page (`collectPlayers`) | players of every order's windows | skips cancelled orders |
| Command palette | cancelled order offered with "Zrušeno" | not offered (deep link still works) |
| Statistiky klubů, per-club status chips | included "Zrušeno N" | chip dropped (`ClubSummaryCard` the same) |
| Club planner order switcher | already left cancelled out (`groupOrders`) | unchanged |
| Přehled "Kluby k vyřízení", attention, notifications of inquiries, main calendar inquiry markers (`inquiries.ts`), `AddToClubOrderDialog`, billing | already `Requested` / `Invited` / live only | unchanged (checked, tests exist) |
| Settings > Služby usage | Invited / Requested / Confirmed | unchanged |
| Notifications | carry the server's text and `actionUrl`; no list of orders on the client | unchanged; a link to a cancelled order opens it read-only |

Club page figures (each checked): **Hráči** = the server's summary (registered / seats) - the client cannot recompute it and cannot see whether the server counts a
cancelled order's seats (see risks); **Termíny** = active windows (a cancelled order's windows are released); **Objednávky** = live orders (already so; now the list
passed in is live too); **Objednáno** = Requested / Confirmed / Completed quotes (cancelled never counted); **Fakturováno / Zaplaceno** = invoices, not orders.

## Open risks

* "Napsat klubu" is gone for cancelled orders (read-only was asked for); say if the desk still needs to message a club about a cancelled order.
* Server-side seat figures (`/club-summary`) are not recomputed; if the server counts a cancelled order's seats in "Hráči", that is a backend question.
* The Historie button count follows the club / date filters of the orders page (the same read).
* The date/reason of a cancellation depends on the history text containing "zruš"; an order cancelled by a path that writes another wording shows a dash.
