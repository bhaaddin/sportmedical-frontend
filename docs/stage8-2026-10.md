- (b) Requested order: the dev data has none (no public form submission was made); drawn by the same code as (c), checked with a copy of
  the Invited order turned into a Requested one in the browser (route), nothing written.
- (d) A staff draft (the unsaved planning of the club planner) is not an order: it is never read, never drawn and never refuses.

Now (`model/pendingHolds.ts`, `board/boardCalendar.ts`, `board/clubHold.ts`):

- The board reads the club-order list once (the cache key the inquiry marks already used) and, on the MAIN calendar only (`mode: 'standard'`):
  - **Requested** days (`requestedDates`, `requestedRanges` with their daily hours) become stand-in club blocks over the opening hours of
    each open calendar of the order's služba: drawn as a hatched, DASHED hold in the club colour, lighter than a confirmed one (hatch
    alpha 62 % of it), label "Rezervováno pro klub X" + "Čeká na potvrzení". They REFUSE a booking exactly like a real club block
    ("Rezervováno pro klub X · čeká na potvrzení").
  - **Invited** days (`offeredDates`) are drawn the same way, lighter still (40 %), dotted, "Nabídnuto klubu X" + "Čeká na odpověď".
    DECISION: they do NOT refuse - the club may decline. A press on the free part of an offered day marks time as everywhere else and asks
    first ("Nabídnuto klubu X ... Přesto rezervovat / Otevřít objednávku / Zrušit"); the window itself ignores the pointer (only its label
    opens the order), so the day stays bookable.
  - **Confirmed, players missing, older server:** a club block with no hold fields is completed from the order list (the order's
    `blocks[].id` is the time block's `clubBlockId`): order id, seats, registered, `playersMissing` -> "Čeká na hráče". Marked
    `holdDerived`, so the "Uvolnit nevyplněné" button (a stage 2 route) is not offered on it. A server that sends the fields is untouched.
  - Cancelled and completed orders hold nothing (R21); a Confirmed order's requested days are not holds (its blocks are).
- Every view: week and day board (windows), month tile (hatched bar with the words), mini calendar (a mark per club, dashed / dotted for
  pending), phone agenda (an entry "Rezervováno pro klub X" with the state) and the phone month list. A click opens the club order
  (the club popover now takes the order id straight from the block, so it needs no read of a block that does not exist yet).
- The old dashed "Poptávka" tag in the day heading stays (it also opens the order, and the club planner's "Klub žádá" marks use it).
- Checks: `scripts/stage8/r22-check.mjs` at 390 / 820 / 1440 - ALL PASSED (a: "Čeká na hráče" on the older API, c: offered holds and the ask,

## R23 - the gap after a wrong click

- Model (`model/gaps.ts`, 17 tests): `busy` is the merged "what is taken" of the booking dialog (`busyIntervals`: closed time, lunch,
  bookings, blocks - a club's hold is a block) plus today's past minutes. LEAD: the hole between the end of what comes before the click and the
  click, `0 < hole < one slot` (the činnost's length when a činnost is chosen in the legend, else the calendar's step) -> ask. TAIL: the hole
  between the booking's end and what follows, `0 < hole < the board step` -> ask. The moved place is offered only when it is itself free
  (never into the lunch, closed time, a club hold, another booking, the past); when it is not, nothing is asked. Tests: gap 0, 5, 10, 25, equal
  to the slot, longer, no previous (nothing before), the opening time as previous, the lunch, a club block, today's past, across midnight
  (clipped end of a late booking), tail cases, the lead-then-tail sequence.
- UI (`board/GapChoice.tsx`, lazy; `board/gapContext.ts`): after "Objednat pacienta" on a marked time the pop-out opens at the click:
  "Hned po předchozím (HH:MM)" / "Přesně jak jsem klikl (HH:MM)" (tail: "Posunout na konec (do HH:MM)" / "Nechat"). Both buttons 44 px, the first is
  focused, Esc / click away closes it and books nothing, no fade when "Animace" is off or reduced. The shared-worker rule adds the same worker's
  other calendars to `busy`. Blocking time and club marks are not asked (only the booking path).
- Real browser (`r23-check.mjs`, desktop, real 40-minute test booking 09:00-09:40, click at 09:45): both labels, 44 px, Esc closes and opens no
  dialog, "Hned po předchozím" opens the booking dialog on 09:40, "Přesně jak jsem klikl" on 09:45: ALL PASSED.
- HONEST GAP: on tablet (820) and phone (390) a synthetic tap / click did not mark a slot in my script (the compact boards use their own touch
  placement), so the pop-out was NOT verified in a real browser at those two sizes; it is a portal with the same component and CSS, 44 px buttons
  and a `max-width: calc(100vw - 24px)` paper, covered by `GapChoice.test.tsx` and the model tests. "The free slot picks" were read as the board's
  free-time marking; the "Nová objednávka" next-free shortcut and the dialog's own slot list are not asked (they list starts the server offers).

## R24 - a club over patients' bookings

- Reproduction: on THIS dev server a club window over a booking is accepted (201 on `POST .../staff` and `PUT .../club-orders/{id}`, both
  tried with a real test booking), so the refusal the owner sees comes from a newer / live server and could not be reproduced here.
  Its problem code is not in the contract, so the dialog treats a refusal as time-taken when it is a 409, or its code / message says
  taken / occupied / overlap (`isTimeTakenRefusal`) - and only then reads the club's calendars for the bookings inside the windows
  (`appointmentsApi.range`); with none in the way the plain refusal stays.
- Flow (`AddToClubOrderDialog` + lazy `ClubConflictStep`, model `clubConflict.ts`, 11 tests): the CONFLICT step lists the colliding
  bookings (patient name as the app shows it, time, činnost, calendar), each with the nearest free start of the same činnost and length
  from the existing availability API (14 days each way, never before today, outside every club window, not on another proposal or a booking
  that stays), a checkbox "Upozornit klienta" per booking (default: the move dialog's remembered choice), and "Přesunout a pokračovat":
  `reschedule` with `notifyPatient`, then the club update is sent again. Nothing moves before the button. A booking with no free slot says
  so and blocks the step. A failing move STOPS, says what already moved and offers "Vrátit přesuny" (moves them back, last first, reports
  any that would not go back). The stage 6 undo bar was not reused (it holds one change); the same `reschedule` call is the undo here.
- Real browser (`r24-check.mjs`, desktop): the first PUT answers 409 through a route (the only simulated step), the real booking, availability,
  reschedule and second PUT run: the step lists the booking, shows a slot, nothing moved before the click, the button is 44 px, no document
  scroll, after the click the booking moved and the order really holds the day: ALL PASSED. Dialog tests (5) cover list, notify choices,
  no slot, failure + revert, plain refusal.
- Not done: the club order wizard (`ClubOrderEntry`, "Nová objednávka klubu") belongs to the club-planning domain and was not changed; a
  tablet / phone browser run of the step (the marking gesture, see R23); the dialog is full screen there and uses the same MUI controls.
